🔌 Backend Bridge Integration Guide

Connect your backend to the generated app for user-specific data and notifications.

1. How It Works

The generated app includes an AppBridge that communicates with your backend using simple HTTPS JSON.

Your backend only needs to expose one endpoint. The app polls this endpoint and processes the JSON response.

2. Configuration

When creating an app in the builder, fill in the Backend Bridge section:

  • Backend URL — e.g., https://api.example.com
  • Auth Mode — none, cookie, or token
  • Notification Mode — polling, websocket, or push
  • Polling Interval — seconds between requests

3. Endpoint Contract

The app calls:

GET {backend_url}/api/app
Authorization: Bearer {token} (if token mode)

Response Format

{
  "version": 1,
  "user": {
    "id": "user_123",
    "token": "jwt_token_here"
  },
  "notifications": [
    {
      "id": "msg_001",
      "title": "Welcome",
      "body": "You have a new message",
      "data": {
        "url": "/dashboard"
      },
      "sent_at": "2026-08-29T12:00:00Z"
    }
  ]
}

4. Authentication

Mode 1: None (Device Only)

The app uses a device ID stored locally. No login required.

Mode 2: Existing Login (Cookie/Session)

The app reuses the website's login. Your backend can set a session cookie, and the bridge automatically sends it.

After login, call this from your frontend:

window.AppBridge.onUserLogin({ id: "user_123", token: "jwt_token" });

Mode 3: Token (JWT)

Your backend issues a JWT, and the app stores it. Send it in the Authorization header.

5. Notifications

Each notification object supports:

FieldTypeDescription
idstringUnique ID
titlestringNotification title
bodystringNotification body
dataobjectOptional deep link data

6. Plugin Actions

The backend can also trigger device plugins by sending an actions array in the response.

Example:

{
  "actions": [
    { "type": "share", "payload": { "text": "Hello", "url": "https://example.com" } },
    { "type": "haptics", "payload": { "style": "impact" } },
    { "type": "clipboard", "payload": { "text": "Copy this code" } }
  ]
}

The app sends action results back to:

POST {backend_url}/api/app/action-result
{ "action": "geolocation", "result": { "coords": ... } }

Foundational plugins (used internally by the bridge):

  • device — device ID
  • network — online/offline detection
  • preferences — local storage
  • splash-screen — native splash

7. Push Notifications (FCM)

To enable real-time push when the app is closed, you need a Firebase project and its google-services.json file.

Steps:

  1. Create a Firebase project at console.firebase.google.com
  2. Add an Android app with the same package name as your generated app
  3. Download google-services.json
  4. Upload it in the builder's Backend Bridge section

The generated app will register with FCM and send its push token to your backend at:

POST {backend_url}/api/app/push-token
{ "token": "fcm_token_here" }

Your backend can then use the token to send push notifications via FCM.

8. Offline Behavior

When offline, notifications are queued locally. When the app reconnects, the queue is flushed automatically.

9. Example Backend (Node.js)

app.get('/api/app', (req, res) => {
  res.json({
    notifications: [
      {
        id: "msg_001",
        title: "Hello",
        body: "Welcome back!"
      }
    ]
  });
});

10. Example Backend (PHP)

<?php
header('Content-Type: application/json');
echo json_encode([
  'notifications' => [
    [
      'id' => 'msg_001',
      'title' => 'Hello',
      'body' => 'Welcome back!'
    ]
  ]
]);
?>
Tip: Keep the JSON simple. The app only needs notifications and optional user data.
